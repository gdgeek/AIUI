# AIUI Contest Polisher

## Contest Workflow

1. Identify the judge-visible promise in one sentence.
2. Make the first screen prove the app belongs on glasses.
3. Keep the live demo under one minute with a clear ending.
4. Prepare a three-minute pitch and fallback path.
5. Separate verified release evidence from aspirational product roadmap.

## Judging Bar

Prefer improvements that increase at least one of these:

- glasses-native value
- demo reliability
- emotional memorability
- technical credibility
- expansion potential

Avoid adding features that make the demo slower, harder to explain, or dependent on fragile live recognition before the release path is proven.

## Handoff Standard

Every contest-facing claim must be backed by one of:

- source file path
- package verification output
- Craft/Lingzhu visible state
- device or release-console evidence
- explicit "future roadmap" label
